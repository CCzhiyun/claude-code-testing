# CCPT 0.36：设计讨论与用量统计

## 终端中的设计讨论

```text
ccpt
/brainstorm 给 20 人团队设计一个请假管理工具，先澄清需求，不要写代码
```

`/brainstorming` 是同一个原生入口，不依赖额外插件。先阅读必要的项目上下文，再逐个问题澄清用户、审批流程和 MVP 范围；信息足够后比较方案并等待反馈。最终文字仍由配置的模型生成，不保证每次措辞或问题顺序一致。

- 方向键移动，Enter 明确确认；数字键只定位，不自动发送。
- 选择 `Type your own answer` 可以自由输入。多选问题用 Space 勾选，移动到 `Submit selected answers` 后确认。
- Esc 关闭问题，不发送默认答案、不继续调用模型。`/questions` 重新打开；也可以直接输入补充信息。
- 回答会写入原来的问题工具结果，然后继续同一个 Agent。批量工具调用遇到提问会停下，后面的调用被标为未执行，不会偷偷继续写文件。
- 此工作流的模型工具仅允许读取、查询、内部任务清单和提问，后续回答仍保留这个限制。模型发出未开放的工具调用也会被拒绝。
- 要进入编码，请 `/clear` 开启新会话，再提出实施要求。不要把讨论结果视为已实施代码。

讨论模式不是操作系统沙箱：配置过的生命周期 Hooks、内部会话和任务记录仍按原配置运行。不要在未审查 Hook 的仓库里把它当成完全无副作用环境。

## token 的三个不同概念

1. **累计用量**：`/usage` 打开统计面板；`/usage details` 查看完整说明。累计每次模型请求的输入与输出，多轮工具调用会重复发送历史，因此累计输入可以大于上下文窗口。
2. **当前上下文**：`/context` 分别显示消息部分的近似量、最后一次请求输入和配置预算。消息估算不包含系统提示、工具定义等，不能用来宣称精确剩余容量。
3. **实时输出**：流式响应期间看到 `~… tokens estimated` 是本地近似值；收到服务端有效 usage 才使用实际计数。中文采用非 ASCII 加权估算，但这不是特定模型的 tokenizer。

新记录的输入总量统一包含缓存。`cacheReadTokens` 和 `cacheWriteTokens` 是其中的明细，不在总数上再次相加。输出中的推理 token 若已包含在接口的输出总量里，也不重复添加。

兼容 Chat Completions 协议的流式请求现在发送 `stream_options.include_usage`，读取最终 usage，而不是累加每一帧的累计值。字段缺失与明确的 0 区分处理；无效、负数、非数值计数不被当成有效用量。依据 [OpenAI 官方接口说明](https://developers.openai.com/api/reference/resources/chat)。

未返回 usage 时，输入和输出分别降级为 `estimated`；旧版本没有记录来源的数据标成 `unknown`，不会篡改旧账或伪称已修复历史账单。新版记录带 `schemaVersion: 2`。实际费用没有可靠报价/计费数据时显示不可用，不把内部的占位 0 美元解释成免费。

限制：中断、失败或网关未发送最终 usage 的请求，可能没有完整的服务端计数；这些本地统计不能替代供应商账单。网关如果不支持标准 streaming usage，需要适配该网关，不能凭空精确计数。

## 本轮验证

- 两个已安装 CLI 在独立目录中实际启动，执行讨论式需求；确认参照端的讨论入口来自插件，并观察到问题选择器、回答后下一题、Esc 取消。
- 旧版 CCPT 缺少 `/brainstorm`，结构化问题显示 JSON；回答仍被当前接口接受，但持久化工具结果不完整。
- 新版通过本地确定性服务与真实 raw-key 输入验证：读文件、选择、取消、重新打开、自定义回答、同 Agent 续聊、批量暂停、拒绝未开放写工具、统计面板。
- 初次真实模型复测收到 429 / 余额不足或无可用资源包。后续切换为 `glm-5.3-flash` 后完成实测：读取 README、展示两轮问题、选择答案、自定义输入、比较两个方案并输出设计，停止等待反馈；未实现业务代码，测试目录 README 的哈希保持不变。该次模型返回了服务端 usage，新记录的计数来源为 reported。

这不是所有功能和 UI 已与参照平台完全一致的声明。

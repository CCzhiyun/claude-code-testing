# 问候与 Skill 调用修复（0.36.1）

## 原因

部分插件的 Skill 描述要求每次对话都调用，模型因此把简单问候误认为工程工作流。
此外，Agent 和菜单使用平台注册表，旧 Skill 工具却只读取独立目录和内置定义，遗漏插件贡献，造成目录中可见的 Skill 执行时报告 Unknown skill。

## 修复

- 纯问候（例如 `Hello 你好`）仍由真实模型回复，但这一轮不提供工具、Skill 目录、工程记忆或仓库上下文，也不创建代码检查点。
- `Hello，帮我修复登录` 不属于纯问候；下一轮开发需求恢复正常工具集，不永久改变会话权限。
- 显式 Skill、工作流指令、委派任务、已关联计划、图片附件及对工具问题的回答不被改成问候流程。
- Skill 描述是能力目录，不是强制执行策略；普通聊天不应自动启动工程流程。
- Skill 工具与 UI 使用同一平台加载入口，支持插件短名称与命名空间名称，并保持禁用规则。原本只能执行、没有列入目录的内置 Skill 作为最低优先级定义保留。不存在的名称仍报错，不伪造 Skill，也不建议反复猜别名。

没有卸载或修改用户的第三方插件。生命周期 Hooks、审计和会话持久化仍执行；纯问候路径不是安全沙箱。

## 验证方法

`bun test ./test/greeting-skills.test.ts` 覆盖纯问候、混合开发需求、工作流边界、问候后继续开发、插件目录与实际执行一致性及禁用别名。
安装后重新打开 `ccpt`，输入 `Hello 你好`，应直接得到自然回复，不出现 skill 工具调用。

本机真实终端验证：0.36.1、`glm-5.3-flash`、用户主目录中保留原插件，输入上述问候后直接回复；持久化会话 `session_e0b72acd797545ac` 中工具调用数为 0。该次请求服务端报告输入 73、输出 136 tokens（输出可能包含模型推理，不等于可见回复字数）。

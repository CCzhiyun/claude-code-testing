测试证据：`permission-safety.test.ts`、`terminal-permission-integration.test.ts`、`api-presets.test.ts`。本地模拟模型主动在被拒绝后重试写文件，测试确认无文件创建；raw-key 场景同时验证 Settings 切换、校验失败不落盘、继续编辑后保存，设置操作零额外模型请求。全面企业验收仍按下方待办分别进行。

## 可复现键盘流程

1. `ccpt` → `/config` → Enter → Space → Esc。更改应丢弃；再次打开仍为原值。
2. `/config` → 输入查询 → Esc清空 → Esc进入列表 → Esc关闭。
3. `/resume` → 输入标题过滤 → Enter。历史应出现；此时不应启动模型或工具。
4. 恢复后 `/branch`。应创建独立会话，但仍不启动模型。下一条普通输入才启动Agent。
5. `/agents` 或 `/tasks` → ←/→切换页签 → 输入过滤词 → Enter详情 → ↑/↓或PageUp/PageDown滚动 → Esc返回 → Ctrl+R刷新。
6. `/theme` → ↑/↓ → Enter应用；Esc取消。`NO_COLOR`仍优先。
7. `/skills` → `/`搜索 → Enter回列表 → Space切换 → Enter保存。停用定义保留在管理界面，但不再进入后续Agent的Skill目录/自动选择；旧会话中已有的历史内容不会被删除，停用不是安全沙箱。
8. `/permissions` → 切换Allow/Ask/Deny → `/`搜索 → Enter回列表 → `d`删除匹配项。Esc先退出搜索，随后关闭。现有托管策略仍优先于项目配置。

恢复其他目录的会话目前会给出明确的目录和恢复命令，而不是悄悄在错误目录运行。已有活跃Agent占用的会话拒绝重复恢复。跨项目自动切换/信任交互仍待实现。

### 真实代码操作的额外差异

独立验收目录中分别准备`sum.cjs`和只读的`test.cjs`，要求修复减法为加法再运行测试。CCPT完成了读文件、改文件、执行Node测试并输出`PARITY-FIXTURE-PASS`；9月20日重新运行CCPT确认读取和测试也成功。

参照CLI的修复流程展示逐文件diff审批，运行`node test.cjs`也出现一次性审批。只确认本次操作，没有选择“以后全部允许”，随后也输出`PARITY-FIXTURE-PASS`。CCPT当前默认策略对同类操作的询问时机不同：**现有权限能力不等于审批体验已经一致**。后续需要独立对照默认策略、逐工具审批、拒绝、会话允许及diff预览；本轮未擅自把所有用户的默认权限规则改掉。

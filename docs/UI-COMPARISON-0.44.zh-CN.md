# CCPT 0.44：终端实测与交互增强

日期：2026-09-24。通过 Windows PTY 实际启动并发送按键，而非仅查看截图或源码。实测全局 CCPT 为 0.42.0、修复前本地构建为 0.43.1，参照终端为 2.1.153。全局安装不会随源码构建自动升级。

## 本轮观察与修复

| 路径 | 观察到的差异 | 本版处理 |
| --- | --- | --- |
| 80 列启动与底栏 | 参照显示简短帮助和推理等级；本项目快捷键与扩展数量挤在一行，后半行被截断 | 优先显示权限模式、推理等级和帮助入口；扩展详情仍在相应管理菜单 |
| 空输入按 `?` | 参照展开本地快捷键，本项目只把问号写入提示词 | 新增本地帮助，`?` / Esc / Enter 收起；继续输入自动返回编辑，不发模型请求。正文中的问号仍是普通文本 |
| `/` 列表 | 本项目为每一项显示很长的参数列，说明空间不足 | 自适应命令列与说明列，选中项单列 Usage；显示当前位置和 Tab / Enter 操作提示 |
| `/config` | 双方都有搜索、选项和分层退出，基本行为接近 | 保留现有交互，不为外观一致改变配置保存/取消语义 |
| 输入 `你好🙂X`，左移一次再退格 | 参照保留 `你好X`；本项目 0.43.1 出现 `你好�X` | 光标与删除按 Unicode 字素簇处理，覆盖 emoji、肤色、组合音标和家庭 emoji |
| 中文终端布局 | 截断和部分换行仍按字符串长度，而非终端格数 | 按显示宽度截断和换行，不切断 emoji 或 ANSI 颜色序列 |
| 启动初始化 | 初始化前可能短暂画出可输入的提示，实际输入尚未可用 | 就绪前只显示初始化状态 |

帮助面板标明默认快捷键；用户自定义绑定仍优先，完整绑定通过 `/keybindings` 查看。Unicode 编辑修复针对默认输入模式，未宣称 Vim 模式全部编辑动作已经对齐。

## 验证范围

新增 `test/prompt-experience.test.ts`：字素编辑、宽度限制、长命令列表、状态栏，以及真实子进程的按键回放。回放检查帮助不发 API、编辑后的文本完整进入模型请求、Tab 补全及 Enter 打开配置仍正常。该测试的模型端是本地夹具，不能代替公司 API 验收。

实测中曾因一次组合按键输入选中参照终端的插件工作流，已用 Esc 中断；未将该流程视为完整工作流验收。后续文字与 Enter 分开发送。

## 尚未声称对齐的内容

- 没有逐一运行所有菜单、插件、语音、移动端和远程 IDE 功能，也不声称像素级一致。
- 原生 scrollback、终端缩放、不同 Windows Terminal / cmd 字体、输入法候选窗仍需设备矩阵测试；自动化回放不是所有终端兼容性证明。
- 没有因此完成 OS 隔离、第三方许可、供应链或公司 Azure/CA/代理/mTLS 的生产验收。
- 未改变用户全局模型、密钥、CA 或全局 npm 安装；未公开发布 npm 包。
